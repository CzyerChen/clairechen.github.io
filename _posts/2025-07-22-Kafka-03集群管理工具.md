
Kafka的运维工具涵盖可视化界面、命令行工具及监控平台，以下按类别整理核心工具及特点：

---

### 📊 **一、可视化运维工具**
1. **Know Streaming**  (YES)
   - **特点**：滴滴开源的一站式管控平台，支持多集群管理、健康巡检、Topic扩缩容、副本迁移等，零侵入支持Kafka 0.10.x-3.x版本。  
   - **适用场景**：企业级生产环境监控与运维。  
   - **项目地址**：[GitHub - didi/KnowStreaming](https://github.com/didi/KnowStreaming)  

2. **CMAK (原Kafka Manager)**  (YES)
   - **特点**：雅虎开源，支持多集群管理、副本选举、分区重分配、Topic配置更新，需依赖ZooKeeper（KRaft模式受限）。  
   - **注意**：需Java 11+和ZooKeeper 3.5+。  
   - **项目地址**：[GitHub - yahoo/CMAK](https://github.com/yahoo/CMAK)  
Kafka 0.8.. or 0.9.. or 0.10.. or 0.11..
Java 11+, up to kafka 3.x

1. **Kafka Assistant**  (NO)
   - **特点**：桌面GUI工具，支持消息查看（JSON/XML格式化）、Broker配置修改、实时仪表盘监控及定时消息发送。  
   - **适用场景**：开发调试与轻量级管理。  
   - **官网**：[http://www.redisant.cn/ka](http://www.redisant.cn/ka)  

2. **Kafka-console-ui**  (YES)
   - **特点**：轻量级Web平台，支持Topic/消费组管理、ACL权限配置，适合中小集群。  
   - **项目地址**：[GitHub - xxd763795151/kafka-console-ui](https://github.com/xxd763795151/kafka-console-ui)  

3. **KafkaQ**  (NO)
   - **特点**：命令行可视化工具，支持分区Offset查询、消息搜索（支持关键词），纯Shell脚本实现，适合Linux服务器直接使用。  
   - **功能示例**：  
     ```bash
     ./KafkaQ-Search.sh --topic logs --partition 0 --search "error"
     ```

---

### ⌨️ **二、命令行工具（Kafka原生）**
1. **主题管理**  
   - **创建/删除Topic**：  
     ```bash
     bin/kafka-topics.sh --create --bootstrap-server localhost:9092 --partitions 3 --topic test
     bin/kafka-topics.sh --delete --topic "test.*"  # 正则删除
     ```
   - **分区扩容**：  
     ```bash
     bin/kafka-topics.sh --alter --topic test --partitions 6
     ```

2. **消息生产与消费**  
   - **控制台生产者/消费者**：  
     ```bash
     bin/kafka-console-producer.sh --broker-list localhost:9092 --topic test
     bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test --from-beginning
     ```

3. **偏移量查询**  
   ```bash
   bin/kafka-consumer-groups.sh --describe --group my-group --bootstrap-server localhost:9092
   ```

4. **元数据与集群管理（KRaft模式）**  
   ```bash
   bin/kafka-metadata-quorum.sh describe --bootstrap-server 192.168.5.169:9092
   ```

---

### ⚙️ **三、监控与诊断工具**
1. **JConsole**  
   - **功能**：基于JMX监控Broker线程、内存、流量（需启用JMX端口）。  
   - **启用方式**：  
     ```bash
     JMX_PORT=9999 bin/kafka-server-start.sh config/server.properties
     ```

2. **Kafka Offset Explorer (原Kafka Tool)**  
   - **功能**：桌面端查看消息内容、消费者滞后量（Lag），支持JSON/XML解析。  

3. **Prometheus + JMX Exporter**  
   - **方案**：通过Java Agent暴露JMX指标，集成Prometheus监控。  
   - **配置示例**：  
     ```bash
     KAFKA_OPTS="-javaagent:jmx_prometheus_javaagent.jar=7070:config.yaml"
     ```

---

### 💎 **工具对比与选型建议**

| **工具类型**       | **代表工具**         | **核心优势**                                      | **适用场景**               |
|--------------------|----------------------|-------------------------------------------------|--------------------------|
| **可视化管控平台** | Know Streaming       | 功能全面，支持运维操作自动化                    | 企业多集群管理           |
| **轻量级Web工具**  | Kafka-console-ui     | 部署简单，中文界面                              | 中小集群日常管理         |
| **命令行增强**     | KafkaQ               | 无需安装，支持消息搜索与Offset查看              | 服务器快速诊断           |
| **监控集成**       | Prometheus+JMX       | 自定义告警，与现有监控栈整合                    | 生产环境指标收集         |

---

### 💎 **总结建议**
- **基础运维**：使用原生命令行工具（如`kafka-topics.sh`）进行快速操作。  
- **可视化监控**：生产环境推荐 **Know Streaming** 或 **CMAK**；开发调试用 **Kafka Assistant**。  
- **问题诊断**：结合 **KafkaQ**（命令行搜索消息）和 **Offset Explorer**（可视化Lag分析）。  
- **安全提示**：生产环境启用JMX时需配置认证与SSL。


Apache Kafka提供了多种运维工具来帮助管理和监控Kafka集群，包括可视化工具和命令行工具。以下是一些常用的工具：

### 可视化工具

1. **Confluent Control Center**(商业NO)：这是由Confluent公司提供的一个企业级的管理工具，它提供了对Kafka集群、KSQL、Schema Registry等组件的全面监控和管理功能。通过直观的用户界面，可以轻松地查看集群状态、消息流、消费者滞后情况等。

2. **Kafka Manager**(YES)：由Yahoo开源，提供了一个Web界面来管理Kafka集群。它可以显示集群的状态、主题详情、消费者组信息，并支持一些基本的管理操作如创建主题、分区等。
Kafka 0.8.. or 0.9.. or 0.10.. or 0.11..
Java 11+，up to kafka 3.x

3. **Kafdrop**：是一个简单的Web UI用于查看Kafka集群中的主题和消息。它不提供复杂的管理功能，但非常适合用来快速浏览和检查集群内容。
Java 17 or newer
Kafka (version 0.11.0 or newer) or Azure Event Hubs
Note: As of Kafdrop 3.10.0, a ZooKeeper connection is no longer required. All necessary cluster information is retrieved via the Kafka admin API.

1. **AKHQ (前身为Kafkahq)**  (YES)：是一个开源的Kafka管理库，提供了一个Web界面来管理和监控Kafka集群。它支持查看主题、消费者组、配置等，并且可以执行一些管理任务。

### 命令行工具

1. **kafka-topics.sh**：这是一个非常重要的命令行工具，用于管理Kafka的主题，包括创建、删除、描述主题以及修改主题配置等操作。

2. **kafka-console-producer.sh 和 kafka-console-consumer.sh**：这两个工具分别用于从命令行发送消息到Kafka主题和消费来自Kafka主题的消息，是调试和测试消息传递非常有用的工具。

3. **kafka-consumer-groups.sh**：用于查看和管理消费者组，包括查看消费者的偏移量、重置偏移量等操作。

4. **kafka-configs.sh**：允许管理员查看和更新Kafka实体（如broker、topic）的配置。

5. **kafka-broker-api-versions.sh**：可以查询指定broker支持的API版本，有助于了解集群中各个节点的能力。

这些工具各有侧重，结合使用可以有效地进行Kafka集群的日常管理和维护工作。无论是开发者还是运维人员，都可以根据需要选择合适的工具来提高工作效率。


在Kafka的生态中，有许多工具用于简化运维、可视化管理和命令行操作，以下是常见的分类整理：


### **一、命令行工具（Kafka自带，位于`bin/`目录下）**  
Kafka官方提供了一系列命令行工具，用于核心操作，是运维的基础工具：  

1. **主题管理**  
   - `kafka-topics.sh`：创建、删除、查看、修改主题（如分区数、副本因子）。  
     示例：`./kafka-topics.sh --bootstrap-server localhost:9092 --list`（列出所有主题）。  

2. **生产/消费消息**  
   - `kafka-console-producer.sh`：命令行生产者，向指定主题发送消息。  
   - `kafka-console-consumer.sh`：命令行消费者，从指定主题消费消息（支持指定分区、起始offset等）。  

3. **消费组管理**  
   - `kafka-consumer-groups.sh`：查看消费组信息、重置offset、删除消费组等。  
     示例：`./kafka-consumer-groups.sh --bootstrap-server localhost:9092 --list`（列出所有消费组）。  

4. **配置管理**  
   - `kafka-configs.sh`：修改主题、 broker 的动态配置（如副本同步因子、权限等）。  

5. **集群状态查看**  
   - `kafka-broker-api-versions.sh`：查看 broker 支持的 API 版本。  
   - `kafka-metadata-quorum.sh`：（Kafka 2.8+）查看元数据集群（KRaft模式）的状态。  

6. **数据迁移/复制**  
   - `kafka-mirror-maker.sh`：跨集群数据同步工具（基于消费者-生产者模式）。  


### **二、运维工具（集群管理、监控、调优）**  
1. **CMAK（Cluster Manager for Apache Kafka）**  (YES)
   - 原名 Kafka Manager，由雅虎开源，后移交社区维护。  
   - 功能：可视化管理集群、主题、分区、消费组；监控 broker 状态、分区分布、副本同步情况；支持创建/修改主题等操作。  
Kafka 0.8.. or 0.9.. or 0.10.. or 0.11..
Java 11+，up to kafka 3.x

2. **Cruise Control**  (NO)
   - 由 LinkedIn 开源，专注于 Kafka 集群的自动运维。  
   - 功能：自动检测集群不平衡（如分区分布不均、负载过高），自动执行分区重平衡；支持限流、故障恢复等，减少人工干预。  
main 分支（原 migrate_to_kafka_2_5 分支）：是当前主要维护的分支，支持 Kafka 2.5 及以上版本，包括 2.5.*、2.6（需 Cruise Control 2.5.11 + 版本）、2.7（需 2.5.36+）、2.8（需 2.5.66+）、3.0（需 2.5.85+）、3.1（需 2.5.85+）、3.8（需 2.5.142+）。
migrate_to_kafka_2_4 分支：仅支持 Kafka 2.4 版本（2.4.*）。
kafka_2_0_to_2_3 分支（已废弃）：支持 Kafka 2.0、2.1、2.2、2.3 版本（2.0.*），但该分支已不再维护。
kafka_0_11_and_1_0 分支（已废弃）：支持更早期的 Kafka 版本（0.11.0.0、1.0、1.1，即 0.1.* 系列），同样已废弃。

3. **Burrow**  (YES)
   - 由 LinkedIn 开源，专注于消费组监控。  
   - 功能：跟踪消费组的 offset 滞后（lag）情况，通过 API 或告警机制通知滞后异常，帮助及时发现消费延迟问题。  

4. **Prometheus + Grafana + JMX Exporter**  (YES)
   - 主流监控组合：JMX Exporter 暴露 Kafka 的 JMX 指标（如 broker 吞吐量、分区副本状态、消费 lag 等），Prometheus 采集指标，Grafana 可视化监控面板。  
   - 适合自定义监控需求，支持告警配置。  

5. **Kafka Monitor**  (NO)
   - 由 Uber 开源，用于测试 Kafka 集群的性能和稳定性。  
   - 功能：模拟生产/消费流量，检测集群在高负载下的表现；监控消息丢失、延迟等异常。  
supports Apache Kafka 0.8 to 2.0

### **三、可视化工具（图形化界面管理）**  
1. **Kafka Tool**  (NO)
   - 桌面端工具（支持 Windows、Mac、Linux），轻量级可视化管理工具。  
   - 功能：查看集群拓扑、主题详情（分区、offset、消息内容）；直接在界面发送/消费消息；管理消费组 offset 等。  

2. **Kowl（原 Kafka Owl）**  (NO)
   - 开源 Web 可视化工具，界面简洁，支持多集群管理。  
   - 功能：实时查看主题消息（支持 JSON、Avro 等格式解析）；监控消费组 lag、分区分布；支持消息搜索和过滤。  

3. **Confluent Control Center**   (商业NO)
   - 商业工具（Confluent 平台核心组件），功能全面。  
   - 功能：集群健康监控、数据流可视化、Schema 管理（集成 Schema Registry）、消费组跟踪；支持自动告警和运维建议。  

4. **Lenses**  (商业NO)
   - 商业工具，专注于 Kafka 数据流管理和监控。  
   - 功能：可视化主题、消息、消费组；支持 SQL 语句查询 Kafka 数据；集成数据质量检查和权限管理。  

5. **AKHQ（Apache Kafka HQ）**  (YES)
   - 开源 Web 工具，基于 Spring Boot 开发。  
   - 功能：集群和主题管理、消息浏览（支持多种格式）、消费组监控、配置管理；支持暗黑模式和多语言。  


这些工具覆盖了Kafka从基础操作到复杂运维的需求，实际使用中可根据场景选择（如开源工具适合低成本需求，商业工具适合企业级复杂环境）。
