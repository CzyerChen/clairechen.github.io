### 1. **Yum 包方式安装 FreeSWITCH**

使用 Yum 包管理器安装 FreeSWITCH 是一种便捷的方式，适用于希望快速部署且不需要高度定制的用户。

**步骤：**

- 添加 FreeSWITCH 官方仓库：
  
  对于 CentOS/RHEL 系统，可以执行以下命令来添加 FreeSWITCH 的官方 yum 仓库：

  ```bash
  sudo curl https://files.freeswitch.org/repo/yum-release/rpm/freeswitch-release-repo-0-1.noarch.rpm -o /usr/src/freeswitch-release-repo-0-1.noarch.rpm
  sudo rpm -Uvh /usr/src/freeswitch-release-repo-0-1.noarch.rpm
  ```

- 安装 FreeSWITCH：

  ```bash
  sudo yum install freeswitch-config-vanilla freeswitch-lang-* freeswitch-sounds-*
  ```

**优点：**

- **简便快捷**：只需几个命令即可完成安装。
- **维护方便**：系统会自动处理依赖关系，并在有更新时提供升级路径。
- **稳定性高**：通常官方仓库中的包已经过测试，较为稳定。

**缺点：**

- **灵活性差**：无法自定义编译选项，可能缺少某些你需要的功能或模块。
- **版本滞后**：yum 包库中的版本可能不是最新的稳定版或特定需求的版本。
- **难以调试**：对于开发和调试来说，yum 安装的方式不如源码安装灵活。

### 2. **源码安装 FreeSWITCH**

源码安装允许你完全控制 FreeSWITCH 的构建过程，包括选择要编译的模块、设置优化参数等。

**步骤：**

- 下载源代码：

  ```bash
  git clone https://freeswitch.org/stash/scm/fs/freeswitch.git -b master freeswitch
  cd freeswitch
  ```

> 这个里面服务器上面的依赖项要考虑的非常多，遇到的问题也非常多，这里就不展开了，后续再具体介绍源码方式安装。

- 编译并安装：

  ```bash
  ./bootstrap.sh
  ./configure
  make
  sudo make install
  sudo make sounds-install moh-install
  ```

**优点：**

- **高度可定制**：可以根据需要启用或禁用特定模块，调整编译选项。
- **最新版本**：能够获取到最新的功能和修复，适合需要最新特性的场景。
- **便于调试与开发**：更易于进行性能调优、问题排查以及二次开发。

**缺点：**

- **复杂度较高**：需要手动解决依赖关系，配置编译选项，安装过程相对复杂。
- **维护成本较大**：更新和维护需要更多工作，如手动下载新版本、重新编译等。

### 3. **Docker 方式安装FreeSWITCH**

Docker安装提供了另一种部署方式，它允许你在容器中运行FreeSWITCH。这种方式可以确保环境的一致性，易于部署和迁移，同时也有助于隔离不同的服务。Dockerfile或预构建的Docker镜像可以用来快速启动一个包含FreeSWITCH的服务。

**步骤：**

```bash
docker run -d --name freeswitch \
 -p 5060:5060/tcp \  #SIP端口
 -p 5060:5060/udp  \ #SIP端口
 -p 5080:5080/tcp \  #备用 SIP 端口
 -p 5080:5080/udp  \ #备用 SIP 端口
 -p 8021:8021/tcp  \ # Event Socket
 -p 16384-32768:16384-32768/udp \  # RTP 媒体端口范围
 -e FS_DISABLE_IPV6=true  -e SOUND_RATES="8000 16000" -e SOUND_TYPES="music default"  \ #环境变量
 --cap-add=IPC_LOCK --cap-add=SYS_NICE    --cap-add=SYS_RESOURCE \ #系统参数
 --ulimit rtprio=99 --ulimit nice=-20  --ulimit nofile=65535:65535 \ #文件描述符
 -v ~/docker/freeswitch/conf:/etc/freeswitch \  #配置文件
 -v ~/docker/freeswitch/data/recordings:/var/lib/freeswitch/recordings  \   #录音文件
 -v ~/docker/freeswitch/data/storage:/var/lib/freeswitch/storage  \  #数据库文件
 -v ~/docker/freeswitch/log:/var/log/freeswitch   \  #日志文件
 -v ~/docker/freeswitch/data/sounds:/usr/share/freeswitch/sounds \  #语音文件
 freeswitch:1.10.12 \  #镜像版本
```

**问题：**

- 以上是和YUM一样跑的类似的一个基础版本，额外需要构建新组件，则需要自行书写Dockerfile，配置专门的镜像来实现
- 官方镜像如果下不下来，可以考虑代理镜像，主要用于较新的版本：docker.xuanyuan.me/safarov/freeswitch:1.10.12
- 容器内部的RTP媒体端口映射，可能受制于外部物理机和内部虚拟环境的限制，因此需要放开

**优点：**

- **环境一致性**：Docker容器确保了开发、测试和生产环境的一致性，减少了“在我的机器上可以工作”的问题。
- **快速部署与扩展**：使用Docker镜像可以快速启动新的FreeSWITCH实例，并且易于水平扩展服务。
- **隔离性**：每个容器都是相互隔离的，这有助于避免不同应用之间的冲突，提高系统的稳定性和安全性。
- **资源优化**：Docker允许细粒度地控制资源分配（如CPU和内存），从而更有效地利用服务器资源。、**简化依赖管理**：所有必要的依赖项都包含在Docker镜像中，避免了复杂的系统级依赖安装过程。
- **便于迁移和备份**：由于整个环境都被封装在容器内，因此更容易进行迁移和备份操作。

**缺点：**

- **性能开销**：尽管Docker提供了很多便利，但容器化可能会带来一定的性能损耗，特别是在网络和存储方面。
- **复杂性增加**：虽然Docker简化了单个应用的部署流程，但它引入了额外的抽象层，增加了系统架构的复杂性。对于不熟悉容器技术的人来说，学习曲线可能较陡峭。
-  **持久化数据管理**：需要特别注意如何处理容器内的持久化数据（如配置文件、日志和数据库）。如果不妥善处理，升级或重启容器时可能会丢失数据。
-   **网络配置挑战**：对于某些复杂的网络拓扑结构，比如SIP通信中的NAT穿越和STUN/TURN服务器设置，可能需要额外的工作来正确配置Docker网络。
-   **监控和维护**：容器化应用需要不同的监控和维护策略，包括健康检查、日志管理和更新机制等。

### **为什么推荐源码安装？**

虽然 Yum 包方式安装 FreeSWITCH 更加简便，但源码安装提供了更高的灵活性和控制力，这使得它成为很多人的首选，尤其是在以下情况下：

1. **需要特定版本**：例如，想要体验最新的功能特性或修复了某个已知问题的版本。
2. **自定义配置**：源码安装允许根据自己的需求选择性地编译模块，关闭不必要的模块以减少资源消耗。
3. **开发和调试**：开发者通常需要对 FreeSWITCH 进行深度定制或调试，源码安装提供了这样的能力。
4. **性能优化**：可以通过调整编译选项来优化 FreeSWITCH 的性能，满足特定环境下的需求。

### **生产环境下的选择**

在生产环境下，选择哪种安装方式取决于具体的需求和团队的技术能力。

如果需要高度定制化或是想要使用最新的稳定版本，那么源码安装可能是更好的选择。

如果更倾向于快速部署并且能够接受官方提供的默认配置，那么yum或Docker安装也能满足需求。

通常，对于大型企业级应用，可能会更倾向于源码安装以保证系统的最佳性能和稳定性。不过，随着Docker技术的发展，越来越多的企业也开始采用Docker来部署和管理他们的应用程序，包括FreeSWITCH。
